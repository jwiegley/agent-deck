Review of e28759a4: viewers_timeout_test.go SIGSTOPs a private tmux server and only an in-process t.Cleanup resumes it. If the run is interrupted (Ctrl-C, go test -timeout, a killed process group), the paused server outlives the binary and its socket stays under /tmp/ad-tmux-*/; scripts/reap-stale-tmux.sh probes each socket with tmux list-sessions and no timeout, so it would hang there. Options: resume from a watchdog process in its own session, use a test-owned Unix socket that never answers, or add a timeout to the reap script's probe. Also, the bind and unbind subtests run serially and each waits the full 5 s tmuxMutationTimeout; running them in parallel saves about 5 s per race-suite run.

** Close Reason

Fixed in dc163e96 (pushed in eba2e06d..ef8209d8, 2026-10-23).
- scripts/reap-stale-tmux.sh bounds every tmux call against a candidate socket by AGENT_DECK_REAPER_PROBE_TIMEOUT (default 5 s).
  - perl forks the call and SIGKILLs it at the deadline. macOS has no GNU timeout, and the tmux client does not die of an inherited SIGALRM.
  - The probe writes to a file, not a $(...) pipe. The client hands its stdout to the server, so a stopped server kept the pipe open after the client died.
  - A server that does not answer is logged and skipped, never killed.
- The viewers test helper starts a watchdog in its own process group that resumes the server after 2 min if the test binary dies. Verified by ending the binary with -test.timeout: the server went from T to S 120 s later.
- The bind and unbind subtests run in parallel.
- tests/ci/reap-stale-tmux.test.sh gains a stopped-server case, and every pass in it is bounded. Before the fix the pass hung until the 120 s outer bound; after, all 30 checks pass in 3 s.
